# CodeHelper 项目分析报告

> 生成时间：2025-06-11
> 项目状态：Active 迭代中

---

## 1. 项目概述
CodeHelper 是使用 Go 语言实现的**终端优先本地 AI 编程助手运行时**，核心设计目标是在用户本地工作区提供可审计、安全可控的端到端 AI 开发体验，不需要绑定特定闭源 IDE 生态，支持通过 CLI、TUI、HTTP/SSE、ACP 协议、Web 控制页等多种方式接入。

### 基础属性
| 项 | 说明 |
| --- | --- |
| 核心语言 | Go 1.26+ |
| 进程入口 | `cmd/codehelper/main.go` |
| 核心定位 | 本地 Agent 运行时 + 多宿主协议层 + 安全执行沙箱 |
| 开源协议 | 内部项目 |

---

## 2. 核心价值
### 2.1 安全优先的执行保障
- 四层递进安全模型，所有工具调用必经统一 Guard 鉴权，不存在强制 bypass 路径，默认 fail-closed 设计
- 密钥仅保存环境变量、系统密钥链引用，不会写入配置文件或日志，架构层面杜绝密钥泄漏风险
- 所有操作全链路留痕可审计，支持会话快照、历史回滚，用户对执行流程拥有完全控制权

### 2.2 多宿主统一协议
同一套核心运行时不需要修改即可对接多种接入形态：
1.  **单次命令执行**：`codehelper exec "需求"` 直接输出 NDJSON 结构化事件流，适合脚本、自动化调用
2.  **交互式终端界面**：`codehelper tui` 提供全键盘操作的终端开发交互界面
3.  **服务模式**：`codehelper serve` 启动 HTTP/SSE 服务，支持远程、第三方客户端接入
4.  **Web 控制页**：`codehelper web` 启动轻量 Web 管理界面，可视化查看会话、审批请求

### 2.3 全能力扩展生态
- 内置覆盖日常开发的全量工具集：文件操作、Shell 执行、代码搜索、Git 操作、代码质量校验、Web 抓取、测试执行等
- 支持 MCP 协议对接外部工具、自定义 Skill 插件、生命周期钩子、LSP 诊断集成
- 内置子 Agent 编排、定时自动化任务、受限工作流引擎，支持复杂多步骤开发流程自动化

## 3. 架构总览
项目采用严格分层设计，依赖方向强约束，禁止跨层调用：
```text
┌─────────────────────────────────────────────────────────────┐
│ Host 层 (internal/host/)                                     │
│  CLI · TUI · WebUI · HTTP/SSE · ACP · 配对连接              │
└────────────────────────────┬────────────────────────────────┘
                             │ Operation/Event 标准协议
┌────────────────────────────▼────────────────────────────────┐
│ Runtime 层 (internal/runtime/)                              │
│  状态机引擎 · Agent 循环 · 依赖装配                          │
└───────┬───────────────┬───────────────┬─────────────────────┘
        │               │               │
┌───────▼───────┐ ┌─────▼───────┐ ┌─────▼────────┐
│ 编排层        │ │ 适配器层     │ │ 持久化/安全层  │
│ Task/Automation│ │ 模型/工具/MCP│ │ 状态存储/沙箱 │
│ Fleet/Workflow│ │ Skill/Hooks  │ │ 权限/审计     │
└───────────────┘ └─────────────┘ └──────────────┘
```

### 核心依赖约束
1.  协议层 `runtime/protocol` 不依赖任何业务实现代码，保证前后向兼容性
2.  Host 层永远不能直接调用工具、模型、沙箱实现，所有请求必须通过 Runtime 接口提交
3.  所有工具执行必须经过 `adapter/tool/guard` 鉴权，不存在绕过路径
4.  Agent 业务循环仅存在于 Runtime 层，UI 层仅负责呈现，不持有业务逻辑

## 4. 核心模块详解
| 模块路径 | 职责说明 |
| --- | --- |
| `internal/host/` | 所有接入形态实现，包括命令行解析、TUI 交互、Web 服务、配对能力 |
| `internal/runtime/` | Agent 状态机核心，负责会话管理、模型调用、工具执行调度 |
| `internal/security/` | 四层安全模型实现，包括会话策略、工作区权限、全局硬约束、操作系统沙箱 |
| `internal/orchestration/` | 任务编排、自动化、子 Agent 池、工作流引擎实现 |
| `internal/adapter/` | 所有扩展点实现，包括模型提供商适配、工具注册、MCP、Skill 插件系统 |
| `internal/persist/` | 会话持久化、快照、操作日志、工作区变更记录存储实现 |
| `internal/platform/` | 操作系统能力封装，包括进程管理、PTY 终端、沙箱后端对接 |
| `internal/observability/` | 遥测、使用统计、诊断日志能力实现 |

## 5. 四层安全模型
项目安全设计是最核心的差异化优势，四层约束逐层递进，不存在全局 bypass 路径：
| 安全层 | 实现位置 | 作用 | 可绕过性 |
| --- | --- | --- | --- |
| 会话策略 | `security/policy` | 控制会话模式（计划/执行/运维）、审批宽松度 | 仅可调整宽松度，无法跳过全局硬约束 |
| 工作区权限 | `security/permissions` | 记忆当前工作区用户允许的操作范围 | 受会话策略约束 |
| 全局硬约束 | `security/constitution` | 系统级不可变安全规则，存储在用户主目录 | **完全不可绕过** |
| 操作系统沙箱 | `security/sandbox` | 执行进程的系统级边界隔离，支持 Seatbelt/Bubblewrap/Landlock 等后端 | 无可用沙箱时自动进入只读模式，不执行危险操作 |

## 7. 技术栈与质量保障
### 技术栈
- 核心语言：Go 1.26+，使用 Wire 做依赖注入装配
- 存储：SQLite + 事件日志 + CAS 内容寻址存储
- TUI 框架：Bubble Tea
- 测试体系：Hermetic 无密钥测试、单元测试、集成测试、安全回归测试

### 内置质量门禁
项目内置自动化校验流程，所有变更提交必须通过：
1.  代码格式、品牌规范检查
2.  Go 语法校验、静态扫描
3.  单元测试 + 并行 Race 检测
4.  密钥泄漏扫描、沙箱攻击测试
5.  端到端命令行、TUI 冒烟测试

## 8. 适用场景
1.  本地开发需要安全可控的 AI 编程辅助，不希望敏感代码上传到公有服务
2.  需要把 AI 能力集成到自研工作流、自动化脚本中，调用标准化 Agent 接口
3.  对执行安全、审计留痕有高要求的内部开发流程场景
4.  希望自定义 AI 助手能力，通过插件、MCP 对接内部系统的场景
